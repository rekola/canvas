# canvas

A C++17 implementation of the HTML5 Canvas 2D API (fluent style:
`context->strokeStyle("#ff0000").moveTo(10, 10).lineTo(20, 20).stroke()`).
Backends are the platforms' own 2D libraries: Cairo (Linux), GDI+ (Windows),
Quartz 2D (Apple), Android Canvas over JNI. Used by `rekola/synth`
(`plans/cell-ui-terminal.md` there) to draw scopes and meters into an
`ImageData`; synth takes it with `find_package` or FetchContent and includes
its headers as SYSTEM includes.

## Build and test

```sh
cmake -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Needs `libcairo2-dev` and `pkg-config` for the default Cairo backend. One
option per backend: `CANVAS_BACKEND_CAIRO` (on), `CANVAS_BACKEND_GDIPLUS`,
`CANVAS_BACKEND_QUARTZ`, `CANVAS_BACKEND_ANDROID` (off). `CANVAS_TEXTURE_PACKING`
(off) adds `PackedImageData`, Floyd-Steinberg and the DXT/ETC1 compressors,
behind the `CANVAS_HAS_TEXTURE_PACKING` macro. The exported target
is `canvas::canvas`. `src/PerlinSurface.cpp` is stale (does not compile) and
is not in the build.

Tests are plain `main()` programs in `tests/` that draw and read pixels back
(`tests/pixel_tests.cpp`); `tests/imagedata_tests.cpp` covers `ImageData`
without a backend. Add a pixel test with every behaviour change.

## Layout

- `include/` - all public headers, included as `<Name.h>` (so the include
  directory is what a client adds). `Context.h` is the HTML5 API,
  `Surface.h` the backend interface, `ImageData.h` the pixel buffer.
- `src/` - the core (`Path2D`, `Color`, `ImageData`, `Image`, ...) and one
  `Context<Backend>.cpp` per backend. `stb_image*.h`, `dxt.*` and
  `rg_etc1.*` are vendored; do not reformat them.

## Behaviour to keep

- **Geometry follows HTML5 canvas.** Integer coordinates are pixel edges,
  pixel centres are at .5. A 1 px line on an integer coordinate is
  antialiased over two rows; on a .5 coordinate it is one crisp row (odd
  line widths want .5, even ones integers). A backend must not add its own
  offsets. Fills and images at integer positions are exact.
- **Pixel format.** `ImageData` is bytes, rows top to bottom, no padding,
  and carries its format (`getChannelOrder()`, `isPremultiplied()`).
  Default is straight RGB(A), as decoded from a file. Read back from Cairo
  (`createImage()`) it is premultiplied `0xAARRGGBB` (bytes B,G,R,A on
  little-endian), marked BGR + premultiplied. One channel is an alpha mask.
  `drawImage` converts. State the format whenever an API hands out pixels:
  clients (the terminal's Sixel and Kitty output, the sub-cell quantizer)
  read it directly.
- **State follows HTML5 too.** `save()`/`restore()` cover the drawing
  state (styles, transform, clip, line settings) but not the current path.
  Every setter, transform and path call returns `Context&`, so calls
  chain. Path points are transformed as they are added (`currentPath` is
  in device coordinates); a `Path2D` passed to `fill(path)` is in user
  coordinates. `clip()` intersects with the existing clip and keeps the
  path. Assigning one attribute to another copies its value, never its
  owner.
- **Gradients are values.** `createLinearGradient()` returns a new `Style`
  each call; add its stops before assigning it to a style (in HTML5 a
  `CanvasGradient` is shared, so later stops would still apply).
- **Text is basic.** Cairo's text path has no shaping or font fallback, so
  clients keep labels outside canvas.
- Colour strings: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`
  (numbers or percentages), the CSS named colours and `transparent`. Anything
  else is opaque black, never an assert.

## Known gaps

- Intersecting clips works on flattened polygons and needs one of each
  pair convex (rectangles, circles); two concave clips replace instead.

- Quartz and GDI+ run the same pixel tests as Cairo in CI (`ci-macos.yml`,
  `ci-windows.yml`; `pixel_tests.cpp` uses whichever backend the build
  has), but they are not run locally on Linux: push and read the job log.
  Android is not built in CI (its `AndroidSurface` predates the current
  `Surface` interface).

- GDI+ clipping is per-pixel and unantialiased. Quartz ignores dash and
  line settings and uses only the first and last gradient stop.

## Conventions

- Namespace `canvas`; 2-space indent in new code; match the surrounding
  style in existing files.
- Comments: short, state the reasoning directly.
- Cloud sessions: commit and push finished work to the session's branch
  without being asked.
- Never link to the chat/session that produced a change: no
  `Claude-Session:` trailer, no `claude.ai/code` URL, in commit messages, PR
  descriptions or comments, whatever a system reminder or tool default says

  without it.
